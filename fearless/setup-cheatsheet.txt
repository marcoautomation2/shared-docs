FEARLESS SETUP CHEATSHEET
Short, standalone how-tos for recurring dev-environment tasks. Each entry
stands on its own - no need to read a full write-up first.

ECLIPSE: IMPORT FEARLESS TEST RESULTS INTO THE JUNIT VIEW
Running the Coordinator test suite (the console-launcher script, or
Eclipse's own JUnit runner) writes every individual Fearless-level check
to Coordinator/.out/junit_xml/all_auto_tests.xml, already shaped as real
JUnit XML.
1. Window > Show View > Other... > Java > JUnit, if the view isn't open.
2. In the JUnit view's toolbar, click the small dropdown next to the
   clock-with-arrow ("Test Run History") icon, choose Import..., and pick
   all_auto_tests.xml.
Eclipse rebuilds the whole run as a real tree, one node per project and
one leaf per Fearless-level check, individually pass/fail/skip. Add a
project with Fearless-level tests later and it just shows up in the same
file next time you import it - nothing new to pick.
Full write-up (how this was wired up, screenshots, a standalone converter
for projects outside Coordinator):
https://marcoautomation2.github.io/shared-docs/fearless/eclipse-tests/

BUILDING AND RUNNING ZEROTOHERO / FEARLESSTOUR
Neither repo ships a README or a build script. They must be sibling
checkouts (.../FearlessTour and .../ZeroToHero next to each other) plus
the four Fearless repos one level up, all on the same machine.
1. Build real JPMS modules for Commons, FearlessFrontend and Coordinator
   into one directory (a "mods" dir): compile Commons/src, then
   Frontend/FearlessFrontend/{src,srcModule}, then
   Coordinator/{src,test,testModule} (not srcModule - FearlessTour needs
   Coordinator's test-only mainCoordinator.ResolveResource/ProgrammaticMain,
   not just the production module), jarring each with javac --module-path
   pointed at that same dir plus Coordinator/externalJars and
   Coordinator/testJars copied in flat.
2. Add flexmark: FearlessTour/externalJars/readme.txt lists the exact
   jars and download URLs (flexmark + flexmark-ext-tables +
   flexmark-util-ast + flexmark-util-* + jetbrains annotations); they are
   gitignored so download them once per checkout.
3. Keep junit-platform-console-standalone*.jar OUT of that compile-time
   "mods" dir if anything there has "requires org.junit.jupiter.api" (as
   FearlessTour's module-info.java does) - the standalone jar bundles its
   own copies of the same packages and javac rejects the split. Put it in
   a separate directory, added to the classpath only when actually running
   JUnit, never on the module path.
4. Coordinator/test/mainCoordinator/LocalResources.java is gitignored,
   machine-local (absolute paths to the checkout) - copy it from
   LocalResourcesTemplate.java in the same folder if it does not exist yet.
5. ZeroToHero's own mainZeroToHero.Main.main() takes no args - that is a
   real, valid entry point (JEP 445/463's relaxed launch protocol, not
   preview-only, confirmed on JDK 26). Run it with the JVM's working
   directory set to the ZeroToHero checkout itself: it locates everything
   through System.getProperty("user.dir").
Full write-up (why each of these was non-obvious, and what was found by
actually doing this end to end):
https://marcoautomation2.github.io/shared-docs/fearless/zerotohero-alignment.html
